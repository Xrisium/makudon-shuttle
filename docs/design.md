# 界面设计与技术栈适用性

## 设计基准

以 Makudon 当前 ui/theme/Theme.kt 的 themePalette 与颜色角色映射为准，配合 docs/design.md 的分组、字体、动效与文案规则。早期文档的“颜色候选”不是生产 token，不能直接复制覆盖当前实现。

设计目标是同一产品家族的严格一致：色彩、字体、图标、圆角、分组、按钮和动效相同；桌面窗口尺寸、鼠标右键、键盘及 DPI 按平台适配，不把手机整屏简单拉宽。

## 字体和组件

- UI 以同源 Noto Sans SC Medium 500 为基准；普通内容 400，语义角色分开。正式字库要覆盖实际中文与用户文件名，不能用例图样本文字子集作为产品字体。
- 英文、数字与中文一并检验；emoji 和缺字有明确回退。为节省体积改成系统字体须另讨论，不能默默改变字形。
- Lucide 统一线性图标，约 1.8–2 线宽；不混杂 emoji 当操作图标，不重画 Makudon 原始品牌图形。
- 页面内边距以 20–24 的逻辑单位起步；组间 16–24，组内 12–16；卡片 / 菜单圆角约 18，具体以并排验收调整。
- 设置采用卡片外次级分类标题 → 一张分组卡片 → 内缩分隔线；同类设置不拆成一排独立小卡。
- 文件清单和正文预览不是设置页，不机械套卡片。选择态、扩展名、路径与长名称有稳定层级。
- 主按钮、描边按钮、文字按钮和分段选择使用同一颜色、圆角及字重体系。
- 保留 Windows 系统标题栏与窗口行为；文件对话框等系统界面接受平台外观，不要求伪装成手机。

手机字号映射参考：标题 20/30、组标题 17/26、常规 14/23、次级 12/20。桌面可按 DPI 和实际视距小幅调整，但不能靠任意缩小字号塞入内容。

主题渐变 240ms，分段选中约 160ms，页面离散切换沿用克制的横向过渡。尊重减少动态效果，不循环装饰，不在文件保存时闪变控件颜色；动画状态不借 disabled 表示。

## 品牌商标

主图标与真实 Fredoka Semibold 600 / 标准宽度字标已整理为[品牌资源](../assets/brand/README.md)，生成来源与参数见 [provenance.json](../assets/brand/provenance.json)。图标保留 Shuttle 原有 M 与纸飞机的路径、线宽和圆端点；文字为完整的 Makudon Shuttle，已全部转路径。Fredoka 只用于设计，不进入应用字体目录、发布包或运行时加载链路。

宽侧栏顶部使用横向组合（宽 220–248），窄侧栏只使用图形；底栏方案在有空间的主页面顶部使用完整组合，避免与产品名重复。设置 → 关于使用居中组合（宽约 320）。窗口和任务栏只用图形；文件清单、正文预览和传输任务让位给内容。保留 Windows 系统标题栏的可访问文本，不为展示商标延长启动时间。

全部跟随当前主题主文字色，保持透明背景、宽高比与安全留白。图片加载时不依赖外部 `color` 穿透 SVG；原生渲染按主题着色，DPI 或主题变化时刷新缓存。具体尺寸、读屏规则与深浅色使用见品牌规范。[品牌与位置预览](../assets/brand/preview.png)是设计示意，当前没有应用代码可接入，不能作为原生截图或发布图标验收。

## 桌面布局

主功能为“文件 / 传输 / 设置”，不沿用手机编辑器的目录管理职责。文件页选择工作位置、查看本地 ZIP、展开库存、打包和解压；传输页选择本地 ZIP、接收确认、任务进度和设备连接；设置页管理外观、语言、工作目录引用及设备记录。

交互例图提供两种导航比较：底栏延续手机三标签，侧栏按桌面宽度适配。两者使用相同 token 和控件，不把布局差异误当成不同品牌风格。最终采用哪种由用户讨论决定。

不提供手机文稿树、远程恢复模式、冲突选择、快照管理、调试日志抓取或“同步全部”。发送完成只能显示“已发送到手机”。

界面不常驻解释网络 / TLS / 缓存原理；必要的覆盖风险、失败原因和下一步就地显示。技术原理放帮助与开发文档。

## egui 能否实现

可以实现这类颜色、圆角、留白、分段控件、菜单、主题过渡与 Lucide 图标。egui 是自绘 GUI，支持样式、字体和自定义绘制，能够建立 Makudon 风格的薄控件层。[egui 官方仓库](https://github.com/emilk/egui)、[eframe 字体与样式入口](https://docs.rs/eframe/latest/eframe/)

它不会自动继承 Compose Material 3：默认按钮、单选、菜单、间距和动效都需适配。字体栅格化、中文输入、屏幕阅读器、窗口缩放及系统对话框也不能只凭一张例图承诺像素一致。

| 部分 | 能力判断 | 实现后的验证 |
| --- | --- | --- |
| 配色、圆角、分组、图标 | 可明确映射 | 逐项 token 和并排截图 |
| 字体与权重 | 可装载字体，正式字重和回退需选定资源 | 中文 / emoji / 长名称，比较同源字体 |
| Material 风格控件 | 需要薄控件皮肤 | 按钮、单选、分段、菜单、弹窗各状态 |
| 动画 | 可维护状态并插值 | 中途切主题、减少动态、空闲无持续重绘 |
| IME、读屏和 DPI | 有平台接入基础 | Win10 x64 真正运行后验收 |

egui 自定义控件也要提供键盘与无障碍语义，不能只画出形状。字体与 GUI 后端会影响体积；不在设计未确认前承诺极小 EXE。

Rust MSVC 目标支持 Windows 10，但这只是语言平台基线，不代表所选 eframe 依赖与显卡组合都已通过。[Rust Windows MSVC 支持](https://doc.rust-lang.org/rustc/platform-support/windows-msvc.html)

## 例图边界

当前例图是可交互设计稿，演示导航、五套主题、ZIP 库存、发送 / 接收、取消及工作目录选择的视觉状态。所有设备、文件、进度和路径为合成示例，不发生文件读写、连接或恢复。

浏览器呈现不等于 Rust 实现，不作为 egui 字体、性能或无障碍验收。确认视觉后，获得编码授权才能做原生对照原型。例图可使用设计字体加载和子集，正式应用需独立确定完整字体策略与许可。
